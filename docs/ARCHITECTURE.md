# 架构与兼容性

```text
fnOS 登录入口
  └─ resmonpro CGI（包用户、只读路由）
       ├─ 原生资源管理组件 + Pro 适配层
       ├─ monitor.py → Pro SQLite
       └─ 温度页 → 127.0.0.1:39188 → 内置温度采集器 → Pro var/temperature SQLite

可选 root DRM 计数读取器 → /run/resmonpro-gpu/engines.json → monitor.py
```

## 资源记录

- CPU / 内存：`/proc`；CPU 温度：`k10temp`、`coretemp`、`zenpower` hwmon。
- 网卡：物理有线网口字节计数差值；排除 Wi-Fi、Docker 和桥接虚拟接口，避免重复累计。
- GPU：当前以 AMD sysfs 为主，保存利用率、温度、显存总量 / 使用量和可选 Compute / Encoder。
- 实时采样每 3 秒，保留约 1 小时缓存，实时窗口显示最近 177 秒、最多 60 个点。
- 长期记录每分钟，保留 30 天。1 / 24 / 168 / 720 小时查询分别按 60 / 300 / 900 / 3600 秒聚合。
- GPU 分钟数据从可用的 3 秒样本平均得到；无值保留空值。

## 温度记录

Pro 内置温度采集器每分钟采样。SQLite 保存采样批次、传感器元数据、温度、阈值、每日统计和采集事件；明细保留 30 天，每日统计保留 365 天，每日备份保留 7 份。仓库不携带历史数据。

Pro 服务统一管理资源与温度两个子进程；任一异常退出时清理两个子进程并将应用标记为停止，避免后台孤儿采集器。温度数据使用 Pro 的 var/temperature 子目录，与资源库分开。温度曲线通过保持形状的三次插值绘制，不修改原始样本；较长缺口断开。图例淡化是显示状态，不会停止后台采集。

## 当前限制

- 原生前端资产文件名与字符串结构来自特定已安装 fnOS 构建；已知文件和哈希见 `fnos-assets.json`。未来版本可能需要更新适配器。
- 没有重新实现原版进程管理后端；运行时仍调用 fnOS 的原生服务和权限体系。
- GPU 的完整功能需要额外安装 root 辅助服务；目前只做过 AMD 780M 验证。
- 硬件型号 / 带宽别名不能从驱动名可靠推断，因此发布源码使用配置覆盖，默认回退到采集名称。
- 窗口尺寸迁移只更新当前应用在 fnOS 用户布局存储中的项目；原生客户端若使用其他窗口机制，可能仍需手动调整。
- macOS 的源码检查不能替代 Linux 采集与 fnOS 桌面验证。

## 手机与 App WebView 布局

当前适配的原版网页模块使用 220px 侧栏、1100px 内容最小宽度和至少三列的总览网格，没有在资源管理模块中发现独立手机网页分支。这不代表手机 App 的原生资源管理页面与网页实现相同。

Pro 的手机视图由 `ui/mobile.js` 提供，复用桌面原生数据适配器及 Pro 历史上下文。未增加采集器或第二份数据库。自动模式在宽度不超过 640px，或触摸设备宽度不超过 1024px 时启用；其余情况使用桌面布局。运行状态工具栏可选择自动 / 手机 / 桌面，选择仅保存在本设备浏览器本地。

手机底部包含运行状态、进程管理和硬件温度。总览按运行时间、资源圆环、横向指标卡片和硬盘列表组织；CPU 使用纵向指标卡片；历史范围使用选择器。进程列表复用原版名称、图标、单位及数据，支持名称 / CPU / 内存排序、搜索、详情和子进程展开，首次展示最多 80 项，按需加载更多。

手机配色优先使用入口主题或同源父窗口主题，否则跟随系统配色；温度 iframe 从 Pro 容器同步配色。底部预留安全区，手机模式不写入桌面窗口尺寸配置。桌面继续使用原版组件。

已验证 320px、390px 竖屏、844px 触摸横屏和 1280px 桌面视口；验证了深浅色、布局切换、CPU 历史范围、触摸读数、服务排序和子进程展开。手机 App 的具体 WebView 与系统字体设置仍需真机确认。
